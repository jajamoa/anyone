The Wrong Person Scores the Same

User-simulator metrics never checked whose response they reward. We run the missing control.

preliminary n = 60 pilot r/AmItheAsshole builds on SUITE

Companion to SUITE (structured user-simulation evaluation with stance / evidence / warrant probes). Numbers on this page are from a small pilot and will change. Last updated 2026-09-02.

Abstract (draft)

Free-text user simulators such as HumanLM and Turing-RL are trained and evaluated with a fidelity score: an LLM judge rates how close a generated response is to the target person's real one. We ask a question none of these papers asks: does the score depend on which person is being simulated? Across 30 papers on human and user simulation, no free-text simulator reports a cross-person control, and none evaluates the reasoning behind an answer against the reasoning the person actually gave. We run the missing control. On matched r/AITA items, swapping the target user's history for another commenter's on the same post moves a HumanLM-style judge score by 2.9 points, within its own resampling noise, and moves embedding cosine by 0.5; the same swap drops structured warrant accuracy from 50 to 25 points, about fifty times its run-to-run noise. We then show why: individual variance in this domain lives in justification, not verdict (warrant entropy 1.15 bits vs stance 0.26 bits on shared posts), so a metric that scores surface content is scoring what everyone shares. We propose reading Toulmin structure (stance, evidence, warrant) off free text with closed-taxonomy probes as the fidelity metric for user simulators, applicable to any generator's output.

01The question

A user simulator is a model that, given some record of a person (their past posts, a profile, an interview), produces what that person would say next. The recent free-text line of work (HumanLM, Turing-RL) trains such models with reinforcement learning, where the reward is a fidelity score: an LLM judge compares the generated reply to the person's real reply and scores how close they are. The same score is then used to evaluate the trained model.

The score has an obvious face validity. A high number means the model wrote something that looks like what the person wrote. But there is a second question underneath it that has not been asked: would the score be any lower if the model had been given the wrong person?

The missing control. Take the target user, replace their history with another commenter's history on the same post, and generate again. If the fidelity metric is about the person, the score should drop. If it is about the post, the genre, or the model's default voice, it will not. Nobody in the free-text simulator line has run this. We did.

The gap is not "their metric is bad". It is that whether the metric is about the person at all has never been measured, and the one comparison that would measure it is missing.

02What the field does now

We checked 30 papers on human and user simulation for two things: what the primary fidelity metric is, and whether any identity control is reported. The full table is in notes/eval-survey.md. Short version:

Three things follow. Similarity scoring is the default only for free-text simulators with a real reply as target, which is exactly where HumanLM and Turing-RL sit. No paper scores the reasoning a model gives against the reasoning the person actually gave (Park explicitly discards the reasoning field, "no ground truth for those"). And identity controls, where they exist, are one-sided: they show more data about the right person helps, never whether data about the wrong person would score as well.

03The control

Setup, kept deliberately close to what these papers already do. Domain is r/AmItheAsshole, the same source as HumanLM's Humanual-Opinion split. For each item we have a post, a target user with a history of past comments, and the target's real comment on this post as ground truth.

  1. same: generate a reply given the target's own history.
  2. cross: generate a reply given another commenter's history on the same post (the donor). Same post, same instructions, wrong person.
  3. same2: generate again with the target's own history, a fresh sample. This is the noise floor.

The quantity of interest is the person effect, score(same) minus score(cross), read against the noise floor, score(same) minus score(same2). A metric that cannot beat its own noise floor is not measuring the person. We report both with a user-clustered paired bootstrap (B = 4000) and summarise as a signal-to-noise ratio.

We score every generation three ways, on the same texts:

HumanLM judge

HumanLM's own rubric prompt: extract key points from the real reply, score coverage minus penalty. Judge model is claude-4.5-haiku, as in their paper.

Embedding cosine

Cosine between generated and real reply, the second HumanLM metric.

Structured probe (SUITE)

Stance (NTA / YTA) and warrant (which of 10 moral principles justifies the verdict), scored against labels extracted from the real comment. Both as direct MCQ and as read off the generated text.

Embedding cosine is flat to the third decimal.

Caveat that decides the next step. The pilot generator (Haiku) fails the manipulation check: its stance under swap is 0.767 in all three conditions, identical, and its warrant sits at the majority-class baseline (0.33 / 0.38 / 0.40) whether or not the person is swapped. Reading structure off Haiku's generated text also sees nothing (person effect −0.05, noise −0.07). So on this generator the three rulers agree, and they agree because the texts do not contain the person. Table A used Sonnet, which does use the context. The clean "same texts, similarity is blind, structure sees" comparison therefore needs the pilot regenerated with a Sonnet-class model. That run is queued.

C. The probe reads structure off real text reliably

A reader model given only a real comment (no post, no history) recovers the SUITE ground-truth labels at 98.3% for stance and 65.0% for warrant (SUITE's human annotator baseline on warrant is 73%). This is the extraction ceiling for applying the structured probe to any free-text simulator's output, method 2 below.

05Why similarity is blind here

Individual variance on a shared post lives in the justification, not the verdict. On posts with at least three commenters in the SUITE data:

LayerEntropy across commenters (bits)Posts where all commenters agree
stance (NTA / YTA)0.2665.3%
warrant (moral principle)1.1513.3%

Two commenters on the same post usually reach the same verdict and usually reach it for different reasons. A metric that scores surface content of the reply (key points, wording, embedding neighbourhood) is scoring the verdict, the scenario facts, and the genre, all of which are shared. The part that differs between people is one clause, the warrant, and a coverage score has no reason to weight it. This also explains why the verdict-level probe (stance) moves so little under swap in Table A: there is little person to find there.

06Proposal: score structure, not similarity

The structured probe is not tied to MCQ-only simulators. Two ways to apply it to any free-text simulator:

Method 1: agent answers the probe

Give the simulator the target's context and the SUITE stance and warrant questions directly (options built from the ground-truth comment plus frequent distractors). This is what SUITE does. It is the cheapest and gives Table A.

Method 2: read the probe off the text

Let the simulator generate freely, hand the text alone to a reader model that answers the same questions, score against ground truth. Works on HumanLM / Turing-RL outputs unchanged. Extraction ceiling 98% / 65% (section 04C).

Both are grounded in argumentation theory (Toulmin: claim, data, warrant) and a closed moral-principle taxonomy in the spirit of Social Chemistry; the warrant labels are discrete, extracted by multi-model vote with human review. The claim is that a fidelity signal for training and evaluating user simulators should be a structural one: it should move when the person changes and stay put when only the sample changes. Similarity signals fail the first test; the warrant probe passes it by a factor of fifty.

A consequence for training: HumanLM and Turing-RL use the similarity score as the RL reward. If the reward does not move under a person swap, the policy is being trained toward a target that is the same for everyone.

07Next steps

  1. Regenerate the 60-item pilot with Sonnet 4.6 (same / cross / same2) so the three rulers can be compared on texts that pass the manipulation check.
  2. Scale to about 200 items, 3 seeds, and report SNR per metric.
  3. Real-vs-real Turing check: give the judge the target's history and ask it to pick between the target's real comment and the donor's real comment. Turing-RL's judge should get this right if it is about the person.
  4. Run the person swap on HumanLM's public Humanual-Opinion test split, scored with their released judge prompt, so the result is on their data.
  5. Score HumanLM's released model outputs with method 2.
